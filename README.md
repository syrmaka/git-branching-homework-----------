# Git Branching Homework

## Описание проекта
Это мини-проект, созданный для отработки навыков работы с ветками Git в VS Code и GitHub. Цель проекта - продемонстрировать правильный процесс разработки: создание новых функций в изолированных ветках, поэтапное добавление изменений через коммиты, слияние веток в основную ветку main и использование Pull Request для проверки кода.

## Использованные ветки
| Ветка | Что делал | Как попала в main |
| `main` | Основная рабочая версия проекта. Хранит финальный результат после всех слияний. | — |
| `feature/profile` | Создан модуль `profile.py` с данными студента. Обновлен `main.py` для вывода профиля. | Слита в `main` через локальное слияние (Merge) и отправлена на GitHub. |
| `feature/subjects` | Создан модуль `subjects.py` со списком учебных дисциплин. Добавлен вызов функции вывода в `main.py`. | Слита в `main` через локальное слияние (Merge) и отправлена на GitHub. |
| `feature/report` | Создан модуль `report.py` для генерации итогового отчёта. Подключён отчёт в `main.py`. | Слита в `main` через **Pull Request** на GitHub (проверка и одобрение перед слиянием). |
| `experiment/broken-idea` | Создана для тренировки удаления ненужной ветки. Создан тестовый файл `broken.py` (или `idea.txt`). | Удалена локально и на GitHub **без слияния** в `main`, чтобы показать изоляцию неудачных экспериментов. |

## Коммиты
1. `create base files` — инициализация репозитория, создание базовых файлов (`README.md`, `.gitignore`, `main.py`).
2. `create new branch and new file profile` — создание ветки `feature/profile` и файла `profile.py`.
3. `update main for new branch` — обновление `main.py` для подключения профиля (слияние `feature/profile` в `main`).
4. `create new branch and new file subjects` — создание ветки `feature/subjects` и файла `subjects.py`.
5. `update file main` — обновление `main.py` для подключения списка дисциплин (слияние `feature/subjects` в `main`).
6. `new file report` — создание файла `report.py` в ветке `feature/report`.
7. `update main for file report` — обновление `main.py` для подключения отчёта (подготовка к PR).
8. `Merge pull request #1 from syrmaka/feature/report` — финальное слияние ветки `feature/report` в `main` через Pull Request.

## Скриншоты
- граф веток до merge;
- результат merge;
- созданный и закрытый Pull Request;
- финальная ветка main на GitHub.

## Вывод
В ходе выполнения работы я убедилась, что
- **Ветвление** позволяет безопасно разрабатывать новые функции, не ломая рабочую версию в `main`.
- **Коммиты** фиксируют каждый шаг: от создания файлов до обновлений `main.py`.
- **Merge** объединяет завершённые ветки в основную линию разработки.
- **Pull Request** служит «мостом» между локальной и удалённой работой, обеспечивая контроль перед финальным слиянием.
